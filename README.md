# VacuumHub

Самостоятельно разворачиваемая платформа с каталогом роботов-пылесосов, библиотекой озвучек и архивом прошивок.

**Статус:** этапы 1–4 из 6 завершены; 5-й (аппаратные адаптеры) и 6-й (production) пока частичные. Для этапа 6 подготовлена production-инфраструктура: двухуровневая админ-защита, аудит, проверки SQLite и безопасный бэкап с проверочным восстановлением. Развёртывание на реальном VDS пока не подтверждено. Этапы 1–4: MVP, каталог устройств, библиотека озвучек и архив прошивок. Go-тесты с `-race` и Docker-сборка прошли в [GitHub Actions](https://github.com/SawaMEN/vacuumhub/actions/runs/42515301018). Развёртывание на реальном VPS ещё не проверено. Публикация прошивок требует отдельно настроенного ClamAV и документированного источника/аппаратной ревизии. Этап 5 частично реализован: доступен только dry-run с журналом; адаптеры реального устройства, установка, откат и восстановление пока не реализованы. [CI программной части этапа 5](https://github.com/SawaMEN/vacuumhub/actions/runs/42517653413) — успешно.

## Возможности MVP

- Русскоязычный адаптивный сайт, каталог моделей, производителей и аппаратных вариантов с фильтрами по региону, ревизии, идентификатору и источнику.
- Административный импорт вариантов JSON, журнал источников идентификаторов, сброс подтверждения при изменении ревизии; без объявления совместимости прошивок.
- REST API на Go, SQLite WAL; зависимости от внешней базы данных нет.
- Панель администратора: модели, загрузка файлов, модерация и публикация.
- SHA-256 при загрузке и повторная проверка перед одобрением.
- Архив прошивок: права и HTTPS-источники, точные аппаратные варианты, проверка ZIP/TAR.GZ, Ed25519 по закреплённым ключам, обязательный ClamAV и журнал версий. Это не инструмент установки.
- Хранение файлов вне публичного веб-каталога.
- Docker Compose, Caddy HTTPS, тесты Go и GitHub Actions CI.

## Развёртывание на VDS/VPS

Понадобятся Linux, Docker Engine, Docker Compose v2, домен с DNS A/AAAA на IP сервера и свободные порты TCP 80/443.

```bash
git clone https://github.com/SawaMEN/vacuumhub.git
cd vacuumhub
cp .env.example .env
openssl rand -hex 32
# Укажите в .env свой DOMAIN и ADMIN_API_TOKEN (случайное значение выше).
# Сгенерируйте bcrypt-хеш пароля для второго уровня доступа к админке:
docker run --rm caddy:2 caddy hash-password --plaintext 'REPLACE_WITH_PRIVATE_LONG_PASSWORD'
# Укажите ADMIN_BASIC_USER и ADMIN_BASIC_HASH в .env, заключив bcrypt-хеш в одинарные кавычки.
chmod 600 .env
docker compose --env-file .env -f deploy/compose.yaml up -d --build
```

После установки открыть `https://ВАШ-ДОМЕН/`; административный интерфейс — `https://ВАШ-ДОМЕН/admin.html`. Caddy запросит логин и пароль Basic Auth, затем интерфейс запросит отдельный ADMIN_API_TOKEN. Для Go Admin API через Caddy применяется заголовок `X-Vacuumhub-Token`. Для публичного сайта дополнительно ограничьте доступ к админке по VPN/IP. На сервере должен быть открыт доступ к HTTPS, а ADMIN_API_TOKEN нельзя публиковать.

Рекомендуется 2 vCPU, 2 ГБ RAM и SSD от 20 ГБ плюс объём будущего архива. До реального запуска на VDS проверены лишь локальные Go-тесты и сборка; Docker-сборка и HTTPS в рабочей среде должны быть проверены отдельно.

## Разработка

```bash
CGO_ENABLED=1 go test -race ./...
CGO_ENABLED=1 go run ./cmd/vacuumhub
```

Для локальной сборки Go 1.23+, компилятор C и `libsqlite3-dev`. Перед запуском задайте `ADMIN_API_TOKEN` (не менее 24 символов). По умолчанию HTTP прослушивает :8080.

## Важные ограничения

Прошивки и голосовые пакеты разрешено распространять только с правами владельцев. Контрольная сумма доказывает целостность файла, но не его безопасность или совместимость с роботом. Не использовать архив для прошивки физических устройств, пока не появился отдельно проверенный адаптер для конкретной аппаратной ревизии.

Проект не связан с производителями и Mindsolo. Лицензия на исходный код пока не выбрана владельцем; публичность репозитория сама по себе не предоставляет прав на использование кода.
