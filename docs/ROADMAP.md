# Карта разработки VacuumHub

Обновлено: 9 ноября 2026 года.

**Всего этапов: 6 · реализовано: 4 · осталось: 2.**

Состояние GitHub: **этапы 1–4 завершены; программная часть 5-го этапа и нативная установка 6-го опубликованы в `main` через [PR #10](https://github.com/SawaMEN/vacuumhub/pull/10).** До фактической установки на VDS оба оставшихся этапа остаются частичными. Реальные аппаратные идентификаторы публикуются только с достоверными источниками.

## Принципы

- Self-hosted: один Linux VDS/VPS; статический Go-бинарник со встроенным сайтом и SQLite, служба systemd, HTTPS непосредственно в Go, без Docker.
- Каталог моделей, библиотека озвучек и архив прошивок без зависимости от Mindsolo.
- Публиковать материалы только при наличии права на распространение и после модерации.
- Контрольная сумма не является доказательством безопасности или совместимости.
- Установка прошивки на физический робот не поддерживается до проверенного адаптера и способа восстановления.
- При завершении каждой задачи обновлять эту карту и тесты.

- [x] Журнал dry-run в SQLite с авторизацией и историей, без хранения исходного hardware ID.
- [x] Админ-интерфейс проверки, HTTP API, автоматические тесты несовпадений, отсутствия доступа и невозможности установки.
- [ ] Реальные адаптеры Xiaomi/Dreame/Roborock для конкретных моделей и ревизий с независимым live-probe.
- [ ] Испытания процедуры восстановления после сбоя на физическом устройстве.
- [ ] Безопасная установка с отдельным подтверждением, журналом операций и проверенным планом восстановления.

**Критерий готовности:** документированы реальные тесты прошивки и восстановления для поддерживаемого варианта. До их проведения `execution_allowed=false` для всех запросов, маршрута записи прошивки нет. **Этап 5 не засчитывается завершённым до аппаратных испытаний.**

См. [INSTALL.md](INSTALL.md): контракт адаптера, API, журнал и требования для допуска к физическому устройству.

**Проверка программной части:** [GitHub Actions, PR #8](https://github.com/SawaMEN/vacuumhub/actions/runs/42517653413) — Go-тесты с race detector, `go vet`, Docker build и JavaScript syntax успешно пройдены. Физическое тестирование не проводилось.

## Этап 6 — нативная установка и production (частично)

**Требование владельца:** полная аналогия нативной установки Firewall-UI, без Docker и без локального запуска; установщик выбирает **только IP или домен**.

- [x] Удалена необходимость в Docker, Caddy, Node.js и компиляторе Go на VDS.
- [x] Веб-интерфейс встроен в один Go-бинарник (`go:embed`), сервер принимает только HTTPS.
- [x] Публичные режимы `ip` и `domain` с проверкой хоста, сертификата SAN и запретом localhost.
- [x] Shell-инсталлятор: меню, загрузка готового релиза по SHA-256, установка systemd, настройка логина/пароля, TLS и порта.
- [x] Управление `sudo vacuumhub`: запуск, остановка, логи, обновление, настройка, пароль, резервная копия и удаление.
- [x] Самоподписанный, существующий PEM или Let's Encrypt; для IP ACME с Certbot ≥5.3 и автоматическим таймером продления.
- [x] Защита админки HTTP Basic поверх HTTPS; CSRF-требование для мутаций, rate-limit и журнал `admin_audit`.
- [x] Нативные бэкап, проверочное восстановление в отдельный временный каталог и ручное восстановление с подтверждением.
- [x] GitHub Actions настроен на тестирование и выпуск статических Linux amd64/arm64 архивов с SHA256SUMS.
- [x] GitHub Actions для [PR #10 / main](https://github.com/SawaMEN/vacuumhub/actions/runs/42534499831) успешно проверил Go-тесты, скрипты и собрал `amd64`/`arm64`; опубликован [релиз v0.7.144](https://github.com/SawaMEN/vacuumhub/releases/tag/v0.7.144) с двумя архивами и SHA256SUMS.
- [ ] Проверить скачивание и установку релиза на целевом VDS/VPS; публикация релиза не равна успешному развёртыванию.
- [ ] Выполнить реальную установку и приёмку HTTPS/авторизации, сертификатов, обновления и восстановления на VDS/VPS.
- [ ] Настроить внешние зашифрованные бэкапы, автоматический мониторинг и ротацию.
- [ ] Для многопользовательского публичного использования реализовать RBAC/MFA, квоты, публичные rate limits и политику удаления.

**Критерий готовности:** нативный запуск на физическом VDS/VPS подтверждён. До этого этап 6 не считается завершённым. Этап 5 также остаётся открытым до аппаратных испытаний робота.

См. [OPERATIONS.md](OPERATIONS.md), [SECURITY.md](SECURITY.md) и [Issue #5](https://github.com/SawaMEN/vacuumhub/issues/5).
