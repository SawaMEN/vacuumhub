# Безопасный архив прошивок (этап 4)

Сервис хранит и публикует **файлы прошивок**. Он **не прошивает робот** и не утверждает, что файл можно безопасно устанавливать на устройство.

## Процедура публикации

1. В каталоге добавить аппаратный вариант с точным `model_slug`, регионом, ревизией и аппаратным ID, который имеет проверяемый HTTPS-источник (`verification=verified`). Это проверка записи каталога человеком, **не техническая проверка совместимости прошивки**.
2. Загрузить файл через панель администратора как `kind=firmware`, указав модель, версию и регион. Он остаётся `pending`.
3. В блоке ожидающего материала заполнить идентификатор варианта, издателя, HTTPS-источник файла, лицензию, права на распространение, HTTPS-документ связи этой версии с ревизией и политику отката. Сохранение: `PATCH /api/v1/admin/firmware/{id}/metadata`.
4. Настроить сервер ClamAV и переменную `FIRMWARE_CLAMD_ADDR`. При публикации сервер ещё раз сверяет SHA-256 сохранённого файла, проверяет ZIP/TAR.GZ либо помечает `.pkg/.bin/.img` как непросмотренный формат, сверяет дополнительную подпись при её наличии, отправляет файл через ClamAV INSTREAM и лишь после ответа `OK` разрешает одобрение.
5. Администратор проверяет юридические права и корректность ссылок **самостоятельно**. Данные сохраняются для истории. Одобрение производится обычным `PATCH /api/v1/admin/assets/{id}` с `{"status":"approved"}`.

**Без ClamAV одобрение любых прошивок отклоняется (fail-closed).** Если ClamAV сообщает об угрозе или недоступен, файл остаётся неопубликованным.

## ClamAV

Переменная `FIRMWARE_CLAMD_ADDR` принимает `host:port` или `unix:/path/to/clamd.sock`. В нативной установке ClamAV запускается отдельной системной службой либо доступен по защищённой внутренней сети. Лучший вариант на одном VDS — Unix-сокет `unix:/run/clamav/clamd.ctl`, доступный системному пользователю `vacuumhub`. Не выставляйте порт 3310 в Интернет; на слабом VDS может потребоваться внешний сканер.

Пример переменных:

```env
FIRMWARE_CLAMD_ADDR=unix:/run/clamav/clamd.ctl
# Optional. Only public keys, no private keys. key-id:64-character-hex; comma-separated:
FIRMWARE_TRUSTED_KEYS=
```

Настройте в ClamAV `StreamMaxLength` **не меньше лимита загрузок (100 MiB)** плюс запас на протокол. Запуск ClamAV на слабом VDS может потребовать дополнительной RAM, поэтому сканер запускается отдельно; он не включён в контейнер приложения. Обновление базы вирусных сигнатур и журнал сканирования обеспечивает оператор.

## Ed25519-подписи

Необязательные поля `signer` (ID ключа) и `signature_hex` (128 hex-символов). Подпись Ed25519 создаётся **над сырыми 32 байтами SHA-256 файла**, не над текстовым представлением. Публичные ключи прикрепляются администратором через `FIRMWARE_TRUSTED_KEYS`:

```env
FIRMWARE_TRUSTED_KEYS=vendor-key-id:012345...64_hex_chars...,second-id:abcdef...64_hex_chars...
```

Статус `trusted_key_signature` подтверждает только проверку относительно **ключа, установленного оператором**. Он **не доказывает, что ключ принадлежит производителю**, пока это не доказано из независимого источника. Без подписи статус `unverified`; файл всё равно может быть опубликован с явно видимым предупреждением о непроверенной подлинности. Неверная подпись или неизвестный ключ блокируют публикацию.

## Статусы

- `status`: `pending/approved/rejected` — решение модератора.
- `firmware_scan_status`: `not_scanned/clean` — результат антивирусной проверки непосредственно перед одобрением.
- `firmware_authenticity`: `unverified/trusted_key_signature` — криптографический результат, не «официальность».
- `firmware_compatibility`: `unverified/documented` — связь с точной ревизией записана и имеет источник; **не является тестом установки**.
- `firmware_inspection`: `zip_checked/tar_checked/opaque_unparsed` — что именно удалось проверить структурно.
- `firmware_downgrade_policy`: `unknown/forbidden/documented`; ограничения отката показываются как данные, не используются для автоматической прошивки.

## API

- `GET /api/v1/firmware?model=...&region=...&variant=...` — только опубликованные, задокументированные и прошедшие сканирование.
- `GET /api/v1/firmware/{id}/details` — происхождение и отдельные статусы.
- `GET /api/v1/firmware/{id}/versions` — история по точному варианту и каналу выпуска.
- `GET /api/v1/assets/{id}/download` — скачивание; старые `approved`-файлы до этапа 4 без подтверждённого сканирования не доступны публично.
- `PATCH /api/v1/admin/firmware/{id}/metadata` — запись происхождения/варианта только для ожидающего публикации файла, Bearer token.
- `PATCH /api/v1/admin/assets/{id}` — одобрение/отклонение, Bearer token.

Один и тот же `variant_id + version + channel` нельзя публиковать дважды. История действий записывается в `firmware_events`. После модерации метаданные неизменяемы через API.

## Ограничения

Структурная проверка архивов запрещает обход путей, ссылки, чрезмерную распаковку и повреждённые записи. Она не обнаруживает вредоносный код как таковой. Проприетарные бинарные форматы пока не декодируются; отдельные парсеры возможны на следующих этапах. HTTPS-ссылка и отмеченный в каталоге аппаратный ID сами по себе не доказывают правдивость источника. Реальное подтверждение совместимости требует специализированных адаптеров и испытаний с физическим устройством (этап 5).

Перед обновлением действующего сервера создайте резервную копию SQLite и файлового хранилища; миграции расширяют существующую схему без удаления старых данных. Старые `approved`-прошивки со статусом `not_scanned` намеренно скрываются из публичного каталога; оператор может повторно отправить их на модерацию после ручной проверки и настройки ClamAV.
