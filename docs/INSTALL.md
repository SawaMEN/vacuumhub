# Этап 5 — предварительная проверка установки прошивки

**Текущий режим: только dry-run. Запись прошивки на устройство отсутствует.** На 9 ноября 2026 г. нет ни одного аппаратно подтверждённого адаптера для роботов. Код не пытается подключаться к пылесосу, менять его настройки или отправлять бинарные файлы.

## Архитектура

`internal/install` — изолированный модуль проверок. Интерфейс `Probe` определяет будущую границу для чтения реальных аппаратных данных из аутентифицированного локального устройства. Адаптеры, выполняющие запись прошивки, не реализованы и не зарегистрированы.

Сервисный `internal/app/install.go` сверяет прошивку из SQLite, SHA-256 файла в хранилище, модель, регион, аппаратную ревизию, подтверждённый аппаратный ID и вручную переданные сведения о текущем состоянии робота. После проверки генерируется отчёт, который **всегда** содержит `decision=blocked` и `execution_allowed=false`.

Для полей, введённых вручную, статус `reported_match` означает только совпадение заявленных значений. Это не подтверждение, что устройство действительно имеет такие характеристики. Проверки без независимого источника имеют статус `unverified`. Системные проверки имеют статусы `pass/fail`.

Пользователь не может передать в запросе права на установку, разрешение обхода preflight или состояние подтверждённого восстановления. Технически маршрут установки отсутствует.

## API (только администратор)

При нативной установке запросы требуют HTTP Basic по HTTPS и заголовок `X-Vacuumhub-Request: same-origin` для POST/PATCH (см. [OPERATIONS.md](OPERATIONS.md)). Ранее используемый Bearer-токен сохраняется только в режиме без заданной пары логин/пароль.

`POST /api/v1/admin/install/dry-runs` принимает, например:

```json
{
  "firmware_id": "0123456789abcdef0123456789abcdef",
  "variant_id": "verified-variant-id",
  "device": {
    "model_slug": "example-model",
    "variant_id": "verified-variant-id",
    "hardware_id": "manually-entered-hardware-id",
    "region": "global",
    "hardware_revision": "r1",
    "installed_version": "1.0.0",
    "battery_percent": 80,
    "charging": true,
    "bootloader": "unknown"
  }
}
```

Пример приведён для понимания схемы, не для реальной прошивки. Платформа не считает введённую информацию доверенной.

Ответ: HTTP 201 и `report.mode=dry_run`, `report.decision=blocked`, `report.execution_allowed=false`, `report.checks[]`. Даже если все вручную заполненные значения совпали с каталогом, выпуск разрешения на установку отсутствует.

Для просмотра журнала:

- `GET /api/v1/admin/install/dry-runs` — последние 50 попыток предварительной проверки.
- `GET /api/v1/admin/install/dry-runs/{id}` — отдельный отчёт.
- `POST /api/v1/admin/install/execute` и любые команды записи прошивки **не существуют**.

Журнал хранится в SQLite в таблице `install_dry_runs` и содержит идентификатор прошивки, вариант, итоговый отчёт, дату. Входящий аппаратный ID не сохраняется в журнале и не возвращается в ответе. Не используйте аппаратные идентификаторы, ключи и токены в публичных issue или логах.

## Условия допуска настоящих адаптеров (ещё не выполнены)

До реализации реальной установки для каждой конкретной модели и ревизии требуется:

1. Документированный, воспроизводимый протокол соединения и аутентификации устройства без обхода механизмов безопасности.
2. Live-проба с независимой проверкой модели, аппаратной ревизии, аппаратного ID, региона, текущей версии, батареи, загрузчика.
3. Криптографическая проверка прошивки там, где это поддерживает производитель, и независимое подтверждение источника.
4. Явно подтверждённая оператором стратегия обновления и правила downgrade. Никаких предположений о порядке версий из текстовых значений.
5. Реально проверенный путь восстановления после неполной записи, отключения питания и сбоя связи, без риска необратимой потери устройства.
6. Отдельное согласие непосредственно перед записью; контроль последовательности действий, идемпотентность и журнал операций.
7. Интеграционные испытания на физическом устройстве соответствующей аппаратной ревизии и рецензирование реализации.
8. Только после этого — отдельная точка включения разрешённого адаптера под конкретный вариант устройства; глобальный флаг установки недопустим.

**Без выполнения этих условий этап 5 остаётся частично выполненным.** Автоматическая прошивка включаться не должна. Гарантии совместимости из одной только записи каталога недостаточны.

## Проверки

`go test -race ./...` проверяет fail-closed режим и маршруты API. Интеграционные тесты покрывают административный доступ, целостность файла, сопоставление модели, региона и ревизии, отсутствие чувствительного аппаратного ID в журнале и отсутствие маршрута записи. Тесты являются программной проверкой, **не испытаниями физического устройства**.

## Развёртывание

Новая миграция SQLite дополняет старую базу таблицей `install_dry_runs`. Перед обновлением действующего VDS создайте резервную копию базы и файлов. Настройка аппаратного адаптера и физическая установка отсутствуют; при запуске не появится новый доступ к роботу.
