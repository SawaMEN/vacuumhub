# Архитектура VacuumHub

## Назначение

Независимая self-hosted платформа для каталога моделей роботов-пылесосов, озвучек и прошивок. Для начальной версии достаточно одного Linux VPS/VDS с 1–2 vCPU, 2 ГБ RAM и SSD (20 ГБ плюс размер архива файлов). Сайт и API доступны на одном HTTPS-домене, не требуются SaaS-сервисы или облачные аккаунты производителей.

### Схема

```text
Браузер (ПК / телефон)
       │
 HTTPS по публичному IP или домену, порт 8443 (настраивается)
       │
  Go-бинарник в systemd, без Docker
       ├── встроенный веб-сайт (go:embed)
       ├── REST API
       ├── Basic Auth (админка) + CSRF-защита
       └── SQLite WAL: /var/lib/vacuumhub/vacuumhub.sqlite
                        /var/lib/vacuumhub/assets/
```

Нативная система работает на одном Linux VDS: не требуются Docker, Caddy, Node.js или отдельный HTTP-прокси. Статический релиз собирается в CI с musl + SQLite и включает веб-ресурсы. TLS завершается непосредственно в Go HTTP-сервере, сертификат и ключ хранятся в `/etc/vacuumhub/tls`. Установщик поддерживает только публичный IP или домен, без режима локального запуска.

## Сущности

`models`:
- `slug` — внутренний идентификатор, первичный ключ.
- `brand`, `name`, `device_id`, `description`, `created_at`.

`assets`:
- `id` — случайный 128-битный идентификатор.
- `kind` — `voicepack` или `firmware`.
- `model_slug` — ссылка на модель.
- `title`, `version`, `language`, `region`, `channel`, `notes`.
- `original_filename`, `storage_filename`, `size_bytes`, `sha256`.
- `status`: `pending`, `approved`, `rejected`.
- `created_at`.

**Совместимость в текущем MVP ограничена связью файла с записью модели.** Поскольку коммерческие названия неоднозначны, нельзя считать модель подтверждённо совместимой без аппаратной ревизии. Это предмет второго и четвёртого этапов.

## Поток публикации

1. Администратор заводит модель.
2. Загружает архив озвучки/прошивки до 100 MiB и указывает метаданные.
3. Сервер сохраняет содержимое вне публичного каталога, генерирует идентификатор и SHA-256.
4. Статус материала — `pending`; публичный каталог и скачивание его не показывают.
5. Администратор отдельно проверяет происхождение, лицензию, безопасность, ревизию и регион.
6. Перед одобрением сервер повторно вычисляет SHA-256.
7. После перевода в `approved` запись появляется в каталоге, а содержимое доступно по download endpoint.

SHA-256 проверяет только целостность файла. Он **не** доказывает безопасность или подлинность прошивки, не заменяет проверку лицензионных условий и аппаратной совместимости.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | /api/v1/health | Проверка процесса |
| GET | /api/v1/models | Список моделей |
| GET | /api/v1/models/{slug} | Модель |
| GET | /api/v1/voicepacks | Одобренные озвучки |
| GET | /api/v1/firmware | Одобренные прошивки |
| GET | /api/v1/assets/{id}/download | Скачать одобренный файл |
| POST | /api/v1/admin/models | Добавить модель |
| POST | /api/v1/admin/assets | Загрузить пакет |
| GET | /api/v1/admin/assets | Очередь модерации |
| PATCH | /api/v1/admin/assets/{id} | Одобрить или отклонить |

В нативном режиме административные маршруты и `/admin.html` защищены HTTP Basic поверх HTTPS, браузерные изменяющие запросы требуют `X-Vacuumhub-Request: same-origin`. Режим токена остаётся только для старых конфигураций и API-тестов. Есть журнал `admin_audit`; RBAC и MFA пока нет.

## Структура исходников

```text
cmd/vacuumhub/              старт приложения
internal/app/               HTTP маршруты, загрузка и модерация
internal/store/             SQLite, миграции, демонстрационный каталог
web/                        статический сайт и админ-панель
deploy/                     systemd-служба, таймер продления, управляющая команда
docs/                       архитектура, безопасность, эксплуатация, карта
.github/workflows/          CI
```

## Расширение платформы

- Каталог v2: manufacturers, model_variants, hardware_revisions, identifiers, проверяемая матрица совместимости.
- Озвучки v2: сведения об авторе и лицензии, форматы, previews, валидация manifest, конвертер для подтверждённых форматов.
- Прошивки v2: подписи, происхождение, история версий, регионы, anti-rollback ограничения, сканирование архивов.
- Установка v2: только изолированные адаптеры проверенных моделей; preflight, dry-run, явное подтверждение и документированное восстановление.
- Нагрузка v2: S3-совместимое хранилище, очереди заданий и отдельные воркеры при необходимости; перенос на PostgreSQL только при обоснованной нагрузке.

## Границы текущего релиза

Отсутствуют подключение к облакам Xiaomi/Dreame/Roborock, автоматическая установка или откат прошивки, генерация озвучек, антивирусный анализ файла и подтверждение совместимости с физическим устройством. Пользователям предлагаются только каталог и скачивание материалов после ручной модерации.
