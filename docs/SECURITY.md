# Безопасность и границы доверия

## Действующие меры в MVP

- Изменяющие операции защищены длинным Bearer-токеном, который задаётся через окружение. Сравнение постоянного времени применяется при одинаковой длине.
- Загрузки получают случайные идентификаторы; клиентское имя файла не используется для формирования имени на диске.
- Файлы находятся вне web-root; публичное скачивание открывается только после одобрения.
- Разрешённые расширения ограничены, размер не превышает 100 MiB.
- SQL-запросы используют подготовленные выражения и привязку параметров.
- При загрузке фиксируется SHA-256; перед одобрением он проверяется повторно.
- Скачивание принудительно использует `attachment`, `application/octet-stream`, `nosniff`.
- Контент архивов не выполняется и не распаковывается приложением.
- Приложение в Docker запускается не от root, контейнер без Linux capabilities, с read-only root filesystem.
- Безопасные HTTP-заголовки: CSP, X-Frame-Options, no-referrer, nosniff.

## Перед массовым публичным запуском

- Ограничить доступ к `/admin.html` и административным endpoint на уровне Caddy, предпочтительно по VPN или IP.
- Ввести RBAC, отдельные учётные записи, MFA, одноразовые сессии и аудит модерации.
- Добавить rate limits, защиту от перебора токена и квоты на загрузку.
- Включить антивирусное/песочничное сканирование и проверку фактического типа файла (magic bytes).
- Для архивов проверять распакованный объём, запрещать zip bombs и вложенные опасные форматы.
- Закреплять версии Docker-образов и зависимостей, проверять обновления через CI.
- Организовать шифрованные резервные копии и периодические тесты восстановления.
- Добавить политику хранения и безопасное удаление отклонённых материалов.

## Прошивки физических роботов

Прошивка для коммерчески одинаковой модели может быть несовместима с её аппаратной ревизией, регионом или загрузчиком. Неправильная версия или anti-rollback могут вывести устройство из строя. MVP **не умеет прошивать устройства**. Будущие адаптеры должны иметь проверенную матрицу совместимости и документированную процедуру восстановления; пользователь должен явно подтвердить действие.

## Юридические ограничения

Нельзя размещать частные/коммерческие прошивки, проприетарные озвучки и чужой контент без разрешения правообладателя. Администратор проверяет право на распространение каждой публикации. SHA-256 не подтверждает подлинность источника или право на распространение.

## Область безопасной эксплуатации

На первом этапе рекомендуется личное или ограниченное использование администратором. Размещение публичного каталога возможно, но расширение пользовательских загрузок без ограничений и сканирования не рекомендуется.
