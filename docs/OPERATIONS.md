# VacuumHub — нативная установка и обслуживание

## Среда

Linux с systemd и `amd64` или `arm64`, VDS/VPS с публичным IPv4/IPv6 или доменом, который указывает на сервер, свободный выбранный TCP-порт, root-доступ. Рекомендуется от 1–2 vCPU, 1–2 ГБ RAM и SSD с местом для каталога и архива.

Установка **не использует Docker и не поддерживает локальный режим**. Сайт и API встроены в Go-бинарник, запуск производится только через systemd. Стандартный адрес: `https://IP:8443/` или `https://домен:8443/`. Никакого `http://localhost` и открытого HTTP API.

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/SawaMEN/vacuumhub/main/install.sh | sudo bash
```

В меню — «Установить / обновить», затем **IP или домен**. Укажите публичный адрес, порт (8443 по умолчанию), сертификат HTTPS и логин/пароль администратора. Инсталлятор загружает подписанный HTTPS-транспортом пакет из GitHub Releases и отдельно проверяет SHA-256 по опубликованному манифесту. В готовом пакете — статический Go-бинарник для `amd64` либо `arm64`, служба systemd, менеджер и скрипты. Компиляция на VDS не требуется.

**Проверка по SHA-256** подтверждает совпадение скачанного архива с опубликованным манифестом в том же GitHub Release; это не независимая криптографическая подпись издателя.

## Сертификаты для IP и домена

Три варианта сертификата:
- Let's Encrypt: автоматический сертификат и обновление; Certbot слушает **TCP 80** при HTTP-01, этот порт должен быть доступен извне и свободен.
- Существующие PEM-файлы: укажите полный путь к сертификату и приватному ключу. Установщик скопирует их в каталог VacuumHub и проверит, что SAN соответствует выбранному IP/домену. Продлевать внешние PEM нужно отдельно.
- Самоподписанный: работает с IP и доменом, обеспечивает шифрование, но **браузер не доверяет сертификату по умолчанию**. Настраивать доверие необходимо вручную; не игнорируйте предупреждение безопасности при передаче пароля.

**Для публичного IP** Let's Encrypt выдаёт короткоживущие сертификаты на ~160 часов; необходим Certbot 5.3+ с `--ip-address` и `--preferred-profile shortlived`. Автоматическую проверку обновления выполняет systemd-таймер `vacuumhub-cert-renew.timer` дважды в день. Продление сертификатов через Certbot и копирование ключей производятся из защищённого каталога в `/etc/vacuumhub/tls` с перезапуском службы после обновления. Смотрите документацию Let's Encrypt о короткоживущих сертификатах.

Если порт 80 занят Firewall-UI или другим веб-сервером, **не останавливайте и не удаляйте его автоматически**: используйте имеющиеся PEM-сертификаты или настройте выпуск сертификата через существующий proxy/ACME-клиент. Если порт панели (например, 8443) занят, выберите другой свободный порт. Правила SSH и чужие правила файрволла установщик не меняет. Разрешите TCP-порт панели в UFW/firewalld и firewall облачного провайдера вручную.

## Авторизация

При нативной установке перед `/admin.html` и административными API браузер запрашивает **HTTP Basic по HTTPS**. Секретная строка хранится в закрытом root-only файле `/etc/vacuumhub/environment` в кодировке Base64 (Base64 **не является шифрованием**). Установщик создаёт длинный технический токен для совместимости с API, но браузерная админка использует логин и пароль. Мутации из браузера требуют дополнительного заголовка `X-Vacuumhub-Request: same-origin`, чтобы блокировать сторонние HTML-формы.

Для одноадминистраторской системы это минимальная модель. RBAC, MFA и отдельные пользовательские сессии остаются задачами публичного многопользовательского режима. Рекомендуется дополнительно ограничить административный доступ по VPN/IP.

## Файлы и служба

| Путь | Назначение |
|---|---|
| `/opt/vacuumhub/vacuumhub` | Статический бинарник со встроенным веб-сайтом |
| `/opt/vacuumhub/install.sh` | Установка, обновление, смена доступа |
| `/usr/local/bin/vacuumhub` | Команда управления |
| `/etc/vacuumhub/environment` | Закрытая конфигурация (0600, root) |
| `/etc/vacuumhub/tls` | Сертификат и приватный ключ |
| `/var/lib/vacuumhub` | SQLite, WAL и озвучки/прошивки |
| `/etc/systemd/system/vacuumhub.service` | systemd-служба, непривилегированный пользователь `vacuumhub` |

```bash
sudo vacuumhub                   # меню
sudo vacuumhub status            # статус и адрес
sudo vacuumhub logs              # последние события
sudo vacuumhub restart           # перезапуск
sudo vacuumhub update            # новый релиз с проверкой SHA-256
sudo vacuumhub configure         # переключить IP/домен, порт, TLS
sudo vacuumhub credentials       # изменить логин/пароль
```

Состояние SQLite: `https://АДРЕС:ПОРТ/api/v1/ready`. Ответ 200 означает доступность базы; `/api/v1/health` подтверждает доступность HTTP-процесса.

## Резервные копии

```bash
sudo vacuumhub backup
# Можно указать свой каталог:
sudo bash /opt/vacuumhub/scripts/backup-native.sh /var/backups/vacuumhub
```

Скрипт останавливает **только** службу VacuumHub, копирует весь `/var/lib/vacuumhub` в один TAR.GZ и отдельно сохраняет `.sha256`. Затем перезапускает ранее работавшую службу даже при ошибке. Архив создаётся с правами только root. Скрипт **не шифрует** копию: перед отправкой во внешнее хранилище зашифруйте её age/GPG и настройте регулярное расписание и уведомления самостоятельно.

Проверка восстановления без изменения рабочей базы:

```bash
sudo vacuumhub restore-test /var/backups/vacuumhub/vacuumhub-ДАТА-PID.tar.gz
```

Она проверяет SHA-256, отклоняет опасные пути и симлинки TAR, разворачивает данные в отдельный временный каталог, вызывает `vacuumhub --verify-data` (целостность SQLite, внешние ключи, размеры и контрольные суммы файлов) и удаляет тестовые данные. **Сервис не перезапускается.**

Реальное восстановление — исключительно по отдельному подтверждению:

```bash
sudo vacuumhub restore /var/backups/vacuumhub/vacuumhub-ДАТА-PID.tar.gz --confirm-overwrite
```

Перед заменой будет сделана свежая копия текущего состояния, затем восстановление и контроль. Старый каталог сохраняется на диске для ручного отката. При неудаче скрипт пытается вернуть предыдущий каталог и запустить службу.

## Обновление и откат

```bash
sudo vacuumhub backup
sudo vacuumhub update
sudo vacuumhub status
```

Инсталлятор сначала загружает и проверяет пакет нового релиза, затем заменяет бинарник и служебные файлы, перезапускает systemd и проверяет, что он работает. При ошибке он возвращает предыдущие бинарник, служебные файлы и конфигурацию. Резервная копия базы необходима независимо от бинарного отката: автоматические миграции SQLite могут менять схему.

## Переход с прежнего Docker Compose (только если он реально уже установлен)

Нативный инсталлятор **не запускает Docker и не переносит тома автоматически**. Для миграции сначала создайте полную резервную копию старого тома через прежнюю версию (см. историю репозитория до нативной установки) и сохраните её вместе с `.sha256` вне сервера. Затем остановите только старые контейнеры VacuumHub, не затрагивая чужие проекты. Установите нативную версию и восстановите данные из проверенного архива через `vacuumhub restore`.

Если на VDS уже работает Firewall-UI, не меняйте его службу или настройки и не занимайте его TCP-порт. Старый Docker Engine не удаляется.

## Удаление

```bash
sudo vacuumhub uninstall
```

Удаляется нативный бинарник и служба systemd. **База, архив и конфигурация сохраняются по умолчанию.** Полная необратимая очистка выполняется только при отдельном выборе подтверждённого удаления.

## Приёмка (ещё требуется на действующем VDS)

- [ ] Бинарник для нужной архитектуры успешно скачан и проверен по SHA-256.
- [ ] Домен/IP, сертификат, входящий порт, правила файрволла работают.
- [ ] `/health`, `/ready`, каталог и административная авторизация отвечают корректно.
- [ ] При неверных данных доступа сервер отвечает 401/429, CSRF-запросы блокируются.
- [ ] Обновление systemd и восстановление старой версии проверены на тестовых данных.
- [ ] Полная резервная копия, восстановление и сверка SHA-256 успешно проведены.
- [ ] Проверено внешнее зашифрованное хранение с уведомлениями.
- [ ] ClamAV подключён для модерации прошивок и не доступен из Интернета.

**До этой приёмки этап production не считается завершённым.**
