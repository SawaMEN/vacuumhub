# VacuumHub — эксплуатация на одном VDS/VPS

## Системные требования и границы

- Linux с Docker Engine, Compose v2 и Docker CLI; небольшой инстанс можно начать с 2 vCPU, 2 ГБ RAM и SSD от 20 ГБ + место под архивы и резервные копии.
- Домен с DNS A/AAAA на VDS, HTTPS с помощью Caddy. Нужны свободные порты 80/443 (TCP и по необходимости UDP 443).
- Если 80/443 уже заняты VPN или другим сайтом, **не запускайте ещё один Caddy с этими портами**. Используйте существующий reverse proxy и перенесите туда конфигурацию HTTPS, Basic Auth и проксирование API. Не переназначайте порты рабочего сервиса без плана миграции.
- Файлы, SQLite, журналы содержатся в Docker volume приложения. Не размещайте SQLite на NFS.
- ClamAV для публикации прошивок настраивается отдельно: \`FIRMWARE_CLAMD_ADDR\`; сканер в основной контейнер на 512 МБ памяти не входит. Без него публикация прошивок блокируется.
- Эти скрипты предназначены для **одного инстанса Docker Compose**, а не для распределённой БД или нескольких серверов.

## Первый запуск / переход со старой версии

\`\`\`bash
git clone https://github.com/SawaMEN/vacuumhub.git
cd vacuumhub
cp .env.example .env
openssl rand -hex 32
# Перенесите случайный токен в ADMIN_API_TOKEN в .env.
docker run --rm caddy:2 caddy hash-password --plaintext 'CHANGE-THIS-LONG-PRIVATE-PASSWORD'
# Замените ADMIN_BASIC_HASH в .env полученным bcrypt-хешем в ОДИНАРНЫХ кавычках.
# Установите ADMIN_BASIC_USER и DOMAIN. Не сохраняйте пароль в командной истории.
chmod 600 .env

docker compose --env-file .env -f deploy/compose.yaml config --quiet
docker compose --env-file .env -f deploy/compose.yaml up -d --build
\`\`\`

**Важно при обновлении уже установленной версии:** новые переменные \`ADMIN_BASIC_USER\` и \`ADMIN_BASIC_HASH\` обязательны. Перенесите их из \`.env.example\` в существующий \`.env\`, **не перезаписывая старый ADMIN_API_TOKEN и FIRMWARE_TRUSTED_KEYS**. Если сервис ещё содержит данные, до обновления выполните резервное копирование.

### Два уровня доступа к админке

Для \`/admin.html\` и \`/api/v1/admin/*\` Caddy требует HTTP Basic поверх TLS. После входа в админку оператор дополнительно вводит \`ADMIN_API_TOKEN\` в форме. JavaScript передаёт этот второй токен в заголовке \`X-Vacuumhub-Token\`, потому что заголовок \`Authorization\` занят HTTP Basic. Прямой Go API (например, при локальных интеграционных тестах) по-прежнему принимает \`Authorization: Bearer <token>\`, но из Интернета доступ к нему должен идти **только** через Caddy.

Основной Go API и порт 8080 нельзя публиковать на внешний интерфейс. Переменная \`TRUST_PROXY_HEADERS=true\` безопасна только когда Caddy переопределяет \`X-Real-IP\` и прямой доступ к приложению закрыт Docker-сетью. При 12 неудачных попытках ввода токена за пять минут источник временно получает HTTP 429.

Текущая модель аутентификации рассчитана на одного администратора. RBAC и MFA ещё не реализованы. Для публичного многопользовательского сервиса дополнительно используйте VPN/allowlist и отдельную учётную модель.

### Состояние сервиса

\`\`\`bash
curl -fsS https://ВАШ-ДОМЕН/api/v1/health
curl -fsS https://ВАШ-ДОМЕН/api/v1/ready
docker compose --env-file .env -f deploy/compose.yaml ps
docker compose --env-file .env -f deploy/compose.yaml logs --tail=100
\`\`\`

\`/health\` — процесс доступен, \`/ready\` — SQLite отвечает на запрос. Docker HEALTHCHECK использует \`/ready\`; Caddy дожидается здорового Go приложения. Длительный статус \`unhealthy\` требует проверки логов и свободного места.

## Резервное копирование

Скрипт работает с реально подключённым volume \`/data\` и не придумывает его имя. На время копирования останавливает приложение, архивирует весь том, проверяет архив и SHA-256 и **попытается перезапустить приложение даже при ошибке**.

\`\`\`bash
sh scripts/backup.sh
# Или в отдельную папку: sh scripts/backup.sh /srv/vacuumhub-backups
\`\`\`

Результат — \`vacuumhub-ДАТА-PID.tar.gz\` и одноимённый файл \`.sha256\`. Архив **не шифруется автоматически**. Храните его вне VDS, используйте шифрование (например, age/GPG) и регулярно удаляйте старые локальные копии по согласованной политике хранения. Скрипт не удаляет копии автоматически. Не храните единственный бэкап на том же сервере.

Рекомендуемый минимальный график: каждый день с отдельным уведомлением о неуспешном завершении команды. Настройте cron/systemd timer в соответствии со своей эксплуатационной политикой.

## Проверка восстановления без риска для работающей платформы

\`\`\`bash
sh scripts/restore-drill.sh /path/to/vacuumhub-YYYYMMDDTHHMMSSZ-PID.tar.gz
\`\`\`

Скрипт сверяет SHA-256, распаковывает архив **в отдельный временный Docker volume**, затем запускает \`vacuumhub --verify-data\` под UID 10001. Команда проверяет целостность SQLite (\`PRAGMA integrity_check\`), ссылки между таблицами и **размер и SHA-256 каждого сохранённого файла**. После проверки временный volume удаляется. Основной сервис не затрагивается. Требуется предварительно собранный Docker image \`app\`.

Операционная проверка на реальном VDS ещё **не выполнена разработчиком**; это часть приёмки шестого этапа.

## Реальное восстановление (разрушительная операция)

\`\`\`bash
sh scripts/restore.sh /path/to/backup.tar.gz --confirm-overwrite
\`\`\`

Скрипт сначала выполняет тест в отдельном томе, создаёт свежий бэкап текущих данных в \`backups/pre-restore\`, затем останавливает приложение, заменяет содержимое рабочего тома данными архива, проверяет его и запускает Go приложение. **При ошибке восстановления приложение намеренно остаётся остановленным**, чтобы не работать с неполной базой. Для повторного восстановления воспользуйтесь предшествующим бэкапом. Не запускайте два восстановления одновременно.

После выполнения проверьте HTTPS, \`/ready\`, опубликованные материалы, скачивание и вход администратора.

## Обновление без потери данных

\`\`\`bash
sh scripts/backup.sh
sh scripts/restore-drill.sh backups/ИМЯ_ПОСЛЕДНЕГО_АРХИВА.tar.gz
git pull --ff-only
docker compose --env-file .env -f deploy/compose.yaml up -d --build
curl -fsS https://ВАШ-ДОМЕН/api/v1/ready
\`\`\`

Если Compose уже использует нестандартное имя проекта (\`-p\` или \`COMPOSE_PROJECT_NAME\`), сохраните эту настройку при запуске скриптов, иначе можно создать другой Docker volume. Не публикуйте токены в git, файлах CI и логах.

## Приёмочный чек-лист на реальном VDS/VPS

- [ ] DNS и TLS сертификат получены корректно; нет конфликта портов с другими сервисами.
- [ ] \`/health\` и \`/ready\` возвращают 200, Docker показывает \`healthy\`.
- [ ] \`/admin.html\` без Basic возвращает 401; с Basic показывает форму второго токена.
- [ ] Admin API без второго токена возвращает 401; после 12 неверных попыток — 429.
- [ ] Admin API авторизован и пишет \`admin_audit\` без сохранения токена.
- [ ] Опубликованные озвучки и прошивки доступны, pending нет; firmware требует ClamAV.
- [ ] Автоматическая запись прошивок отсутствует, dry-run всегда заблокирован.
- [ ] Архив, его SHA-256 и восстановление в отдельный том проверены.
- [ ] Бэкапы копируются в защищённое внешнее хранилище, процедура восстановления задокументирована.
- [ ] Логи и свободное место на диске наблюдаются; при необходимости подключён внешний мониторинг.
